Linked-read FASTQ files can take several forms. We **strongly** advocate for the [standard format](https://blinkseq.github.io/lastq/)
and provide a converter for it, but Djinn can operate on haplotagging (v1), BLink-seq, stLFR, 10X, and TELL-seq data formats
The general form of those commands is:

```bash
djinn fastq command <options> inputs...
```

 Many `djinn fastq` commands have a required argument `PREFIX` that sets a prefix
 for writing new FASTQ files. Diagnostics may sombetimes be written to stdout/stderr.

## Barcode technologies
Djinn auto-detects FASTQ format and barcode type, with expectations like those described
[here](https://blinkseq.github.io/linkedreads/info/#linked-read-varieties). Mix-matching
FASTQ and barcode format will confuse the software and is not recommended. As an example,
having an stLFR barcode (`1_2_3`) suffixed on a read ID with a colon (`:`) like TELL-seq
does will fail (stLFR expects `#` separator). Using the standard format (`BX:Z` and `VX:i` tags),
will allow any barcode style.
