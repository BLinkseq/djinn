You might want a table of the counts (frequency) of all the unique barcodes in your data and that's what `count`
is for. Records with missing barcodes are ignored. Writes to `stdout`.

You can use one file of a pair (e.g. R1 or R2), but including both files will prioritize counting the first file
and only count occurences of _new_ barcodes in the second file that aren't present in the first file. This is done
to avoid double-counting barcodes.

Format is auto-detected from the first 100 records for haplotagging, TELLseq, and stLFR. 10X data
cannot be auto-detected this way (its barcode is just the first 16 bases of R1, with nothing marking
it as a barcode), so counting 10X barcodes requires `--bc-list`: either a path to your own
whitelist, or the literal value `10x` to use the official 10X Genomics whitelist embedded in Djinn.
For 10X input, only the first file (R1) is read, since that's the only place the barcode lives.


## Usage
```bash
count file.R1.fq.gz [file.R2.fq.gz]
```

Example: count only valid barcodes
```bash
djinn fq count sample1.F.fq.gz sample1.R.fq.gz > sample1.bxcount
```

## Options
| argument          | description                                                                   |
|:------------------|:------------------------------------------------------------------------------|
| `file.R*.fq.gz`   | FASTQ file or file pair <Badge text="required" variant="tip" />                          |
| `-i` `--invalid`  | Include invalid barcodes                                                      |
| `-b` `--bc-list`  | Valid barcode list, or literal `10x` for the embedded official whitelist <Badge text="required: for 10X Genomics input" variant="tip" /> |
