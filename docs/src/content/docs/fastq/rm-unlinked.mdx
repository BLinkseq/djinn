In order for reads to be "linked", they must share a barcode with at least one other read pair. Reads or
read-pairs that do not share a barcode are unlinked and sometimes called singletons. Use `rm-unlinked` to
to isolate records with meaningful linked-read information. If you want to keep a separate
file (or files) of unlinked/singleton records, use the `--unlinked` flag. Barcodes are counted
per read-pair or unpair read.

Format is auto-detected from the first 100 records for haplotagging, TELLseq, and stLFR. 10X data
cannot be auto-detected this way (its barcode is just the first 16 bases of R1, with nothing marking
it as a barcode), so filtering 10X data requires `--bc-list`: either a path to your own whitelist,
or the literal value `10x` to use the official 10X Genomics whitelist embedded in Djinn.

## Usage

```bash
rm-unlinked [--unlinked] PREFIX file.R1.fq.gz [file.R2.fq.gz]
```

Example: remove unlinked barcodes and retain them in a separate file
```bash 
djinn fq rm-unlinked --unlinked hyena.clean hyena.R*.fq.gz
```

## Options
| argument            | description                                                                        |
| :------------------ | :--------------------------------------------------------------------------------- |
| `PREFIX`          |  output filename prefix   <Badge text="required" variant="tip" />    |
| `file.R*.fq.gz`             | FASTQ file or file pair <Badge text="required" variant="tip" />                               |
| `--bc-count`   | write valid barcode counts to `PREFIX.count` <Badge text="optional" variant="note" />    |
| `-u` `--unlinked`   | write valid singleton records to `PREFIX.unlinked`                                |
| `-b` `--bc-list`  | Valid barcode list, or literal `10x` for the embedded official whitelist <Badge text="required: for 10X Genomics input" variant="tip" /> |
